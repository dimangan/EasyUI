# Предисловие
Приложение было написано для личного использования, потому что автор устал постоянно ручками настраивать новые ВПН сервера, потому что они с некоторой периодичностью улетают в бан по ip.
- В текущей версии генерируемые инбаунды работают стабильно, кроме Vless TCP Reality (зависит от провайдера)
- Если какой-либо инбаунд не работает - попробуйте пересоздать его на другом порту.
- При создании инбаунда в фаерволе открывается соответствующий инбаунду порт (ufw allow port), аналогично при удалении инбаунда порт закрывается (ufw delete allow port).
- Для транспорта XHTTP предусмотрено создание инбаунда без security на порту 8080, в такой конфигурации будет использоваться TLS через nginx. Иные конфиги без security не имеют смысла.

# EasyUI

EasyUI — веб-панель для централизованного управления серверами с **3x-ui**, подключениями и пользователями. Она помогает подготовить удалённые серверы по SSH, создать на них инбаунды, назначить пользователям доступ и выдать одну ссылку подписки с подключениями с разных серверов.

Панель написана на Java 17 и Spring Boot, интерфейс — на Angular. Данные хранятся в PostgreSQL. После установки интерфейс и API работают из одного JAR за Nginx с HTTPS.

## Основные возможности

- Добавление серверов с IP-адресом, доменом и данными SSH; использование общей пары ключей или собственной пары для сервера.
- Пошаговая настройка удалённого сервера: SSH-ключи, UFW, Nginx, сертификат, установка и настройка 3x-ui. В интерфейсе видны статус и текущий этап настройки.
- Просмотр, создание и удаление инбаундов. В форме доступны VLESS с TCP, gRPC или XHTTP, Hysteria с UDP, параметры TLS и REALITY.
- Создание и удаление пользователей, просмотр суммарного трафика, полученного с серверов 3x-ui.
- Назначение и снятие доступа пользователя к отдельным инбаундам на разных серверах.
- Получение персональной ссылки подписки и QR-кода для импорта в совместимый клиент.
- Изменение логина и пароля администратора через интерфейс.

**Инбаунд** — точка входа на сервере 3x-ui: протокол, транспорт, порт и параметры защиты. Пользователи в разделе «Пользователи» — получатели подключений и подписок; вход в административную панель выполняется отдельной учётной записью администратора.

## Требования для установки панели

- Debian **12** либо Ubuntu **24.04 / 26.04**, запущенная с systemd.
- Доступ к серверу с правами root или через `sudo`.
- Домен, DNS-записи которого указывают на IP этого сервера. Если есть запись AAAA, IPv6 тоже должен вести на него.
- Доступные извне TCP-порты **80 и 443**, в том числе в сетевом экране хостинг-провайдера. Порт 80 нужен для выпуска и последующего продления сертификата Let's Encrypt.
- Доступ в интернет для скачивания пакетов, файлов с GitHub и обращения к Let's Encrypt.

Рекомендуется отдельный сервер для панели: установщик устанавливает PostgreSQL и Nginx, записывает конфигурацию сайта и включает UFW с разрешениями для TCP-портов **22, 80 и 443**. Если SSH использует другой порт, заранее разрешите его в UFW, чтобы сохранить доступ.

## Установка

Команды выполняются на сервере, где будет работать EasyUI. Если `curl` ещё не установлен:

```bash
sudo apt-get update
sudo apt-get install -y curl ca-certificates
```

Замените `example.com` своим доменом и выполните:

```bash
curl -fL https://raw.githubusercontent.com/dimangan/EasyUI/refs/heads/master/install.sh -o install.sh && sudo bash install.sh example.com
```

Скрипт принимает **ровно один аргумент — домен**: без `https://`, порта и пути. Для кириллического домена используйте Punycode. Справка доступна через `bash install.sh --help`.

Установщик скачает JAR, `application.properties` и два шаблона из `setup/`, установит Java 17, PostgreSQL, Nginx и Certbot. Затем он создаст системного пользователя `easy-ui`, базу `easy_ui` с отдельной учётной записью, выпустит сертификат Let's Encrypt и запустит сервис `easy-ui.service` с автозапуском. Продление сертификата выполняется через `certbot.timer`.

Приложение слушает `127.0.0.1:8080`; публичные запросы обслуживает Nginx на HTTPS. После успешного завершения откройте `https://example.com/` со своим доменом.

## Первый вход

При первой установке:

- **Логин:** `admin`.
- **Пароль:** случайный, сгенерированный установщиком. Он выводится в конце установки в строке `Initial admin password`.

Если вывод терминала потерян, стартовый пароль можно посмотреть на сервере:

```bash
sudo sed -n 's/^-p=//p' /etc/EasyUI/java.args
```

Это стартовое значение: после смены пароля в интерфейсе содержимое `java.args` не обновляется. Пароль также присутствует в журнале первоначальной установки `/var/log/easy-ui-install.*.log`; храните этот журнал как файл с данными доступа.

В правом верхнем углу откройте меню **«Администратор» → «Изменить логин и пароль»** и задайте свои данные.

**Особенность смены логина:** при каждом запуске приложение проверяет наличие администратора с именем из аргумента `-u=` (по умолчанию `admin`). Если переименовать `admin` только через интерфейс, после перезапуска он будет создан снова со стартовым паролем из `java.args`. Чтобы этого избежать, можно сохранить логин `admin` и изменить только пароль. При выборе другого логина согласуйте с ним аргумент `-u=НОВЫЙ_ЛОГИН` в `/etc/EasyUI/java.args` до перезапуска сервиса.

## Как работать с панелью

### 1. Добавьте и настройте сервер

Панель EasyUI и управляемый сервер — разные роли. Для первого подключения подготовьте отдельный сервер с Ubuntu 24.04, доступом по SSH и собственным доменом, указывающим на его IP. Автонастройка использует `apt`, `sudo`, UFW и systemd; с сервера EasyUI должны быть доступны SSH и будущий HTTPS-порт панели 3x-ui.

В разделе **«Серверы»** нажмите **«Добавить сервер»** и укажите название, IP-адрес, SSH-порт, пользователя, пароль и домен. Пользователю нужны права `sudo`; при начальном подключении под `root` приложение создаёт отдельного sudo-пользователя. По умолчанию используется пара SSH-ключей, которую EasyUI генерирует при первом запуске. Свою пару можно задать флажком **«Указать пару ключей»**; пароль для первоначальной настройки всё равно нужен.

Нажмите **«Настроить»** и подтвердите действие. Оно изменяет удалённый сервер: устанавливает пакеты и 3x-ui, добавляет SSH-ключ, включает UFW, выпускает сертификат и записывает конфигурацию Nginx и сайт-заглушку. Домен должен быть доступен для проверки сертификата по порту 80. Внешний сетевой экран провайдера настраивается отдельно.

Нажимайте **«Обновить»**, чтобы видеть ход настройки. После статуса **«Работает»** и этапа **«Настроен»** станут доступны **«Инбаунды»** и ссылка **«3x-ui панель»**. При ошибке проверьте журналы EasyUI и повторите **«Настроить»**: процесс продолжает работу с сохранённого этапа.

Кнопка **«Удалить»** убирает сервер из базы EasyUI; удалённые 3x-ui, Nginx и другие установленные компоненты остаются на сервере.

### 2. Создайте инбаунды

В строке настроенного сервера откройте **«Инбаунды» → «Добавить инбаунд»**. Выберите флаг, название, протокол, транспорт, защиту и при необходимости порт. Если порт не указан, приложение подбирает его автоматически. Создание и удаление инбаунда также меняет правила UFW на управляемом сервере; разрешения во внешнем сетевом экране при необходимости добавьте самостоятельно.

### 3. Создайте пользователя и назначьте доступ

Откройте **«Пользователи» → «Добавить пользователя»** и задайте уникальное имя. Приложение создаёт данные подключения и отправляет пользователя в 3x-ui на добавленных серверах.

В строке пользователя откройте **«Инбаунды»**, отметьте нужные точки входа по серверам и нажмите **«Сохранить изменения»**. Снятие отметки убирает назначение. Если сервер недоступен или изменения не подтверждены, интерфейс покажет сообщение — проверьте подключение и повторите операцию.

### 4. Выдайте подписку

В строке пользователя нажмите **«Подписка»**. Скопируйте ссылку или отсканируйте QR-код в клиенте, поддерживающем выбранные протоколы и импорт подписок. Адрес имеет вид `https://example.com/sub/ИДЕНТИФИКАТОР` и объединяет подключения пользователя с серверов 3x-ui.

Для получения подписки не требуется вход администратора: передавайте эту ссылку только её владельцу. Если список подключений пуст, проверьте назначения инбаундов и доступность серверов.

## Обслуживание и диагностика

Состояние, запуск, остановка и перезапуск панели:

```bash
sudo systemctl status easy-ui.service
sudo systemctl start easy-ui.service
sudo systemctl stop easy-ui.service
sudo systemctl restart easy-ui.service
```

Последние сообщения и просмотр журнала в реальном времени:

```bash
sudo journalctl -u easy-ui.service -n 100 --no-pager
sudo journalctl -u easy-ui.service -f
```

Проверка связанных компонентов:

```bash
sudo systemctl status postgresql nginx
sudo nginx -t
sudo systemctl status certbot.timer
curl -f http://127.0.0.1:8080/ -o /dev/null
```

Локальный `curl` проверяет ответ приложения без Nginx. Если приложение отвечает локально, но сайт не открывается по домену, проверьте DNS, правила сети, состояние Nginx и сертификат. Если установка прервалась, её журнал находится в `/var/log/easy-ui-install.*.log`; сообщение об ошибке содержит этап и номер строки.

### Основные файлы

| Путь на сервере | Назначение |
| --- | --- |
| `/etc/EasyUI/EasyUI.jar` | Исполняемый файл приложения с веб-интерфейсом |
| `/etc/EasyUI/application.properties` | Внешняя конфигурация приложения и подключения к БД |
| `/etc/EasyUI/java.args` | Аргументы запуска Java и стартовые данные администратора |
| `/etc/EasyUI/db.credentials` | Сгенерированные имя и пароль роли PostgreSQL |
| `/etc/EasyUI/setup/nginx.config`, `/etc/EasyUI/setup/index.html` | Шаблоны для настройки управляемых серверов |
| `/etc/EasyUI/logs/application.log` | Файловый журнал приложения |
| `/etc/systemd/system/easy-ui.service` | Описание сервиса systemd |
| `/etc/nginx/conf.d/easy-ui.conf` | Конфигурация публичного сайта EasyUI |
| `/etc/letsencrypt/live/` | Сертификаты, выпущенные Certbot |

Для изменения конфигурации используйте `sudoedit /etc/EasyUI/application.properties`, затем перезапустите `easy-ui.service`. Аргументы из `java.args`, включая адрес и порт приложения, имеют приоритет над properties. Настройки серверов, пользователи и SSH-ключи хранятся в базе PostgreSQL `easy_ui`, поэтому одной копии каталога `/etc/EasyUI` недостаточно для резервного копирования всех данных.

### Повторный запуск и обновление

Перед обновлением сохраните резервную копию базы PostgreSQL `easy_ui` и каталога `/etc/EasyUI`. Повторно скачайте и выполните команду из раздела «Установка» с тем же доменом.

При повторном запуске скрипт скачивает JAR и шаблоны заново, заменяет их, перезаписывает описание сервиса и конфигурацию сайта Nginx, выполняет системные этапы установки и перезапускает приложение. Во время перезапуска возможен краткий перерыв в работе. Уже существующие `application.properties`, `java.args` и `db.credentials` сохраняются; база не удаляется. Новая версия `application.properties` из репозитория автоматически не применяется — нужные изменения в существующую конфигурацию вносите отдельно.

Загрузка производится из ветки `master`. Автоматический откат версии или изменений схемы БД установщиком не предусмотрен.
